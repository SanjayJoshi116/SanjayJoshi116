## Context

`scripts/render_profile.py` renders everything in memory and writes only if every step succeeds. Today it replaces one README region (`<!-- featured:start … -->` to `<!-- featured:end -->`) with `featured_block()`. `gather()` already fetches the owner's public repos without auth (`/users/{user}/repos`), so the public table needs no new API call or token scope. Private copy lives in `featured.private`. The All projects list and the hero and stack `<img>` tags are hand-written. See proposal.md (Why) for the drift this causes.

The specs this change extends still live in `openspec/changes/glass-profile-readme/specs/`; that change is not archived yet.

## Goals / Non-Goals

**Goals:**
- Every README fact that also exists in `profile.yml` or the API is generated.
- The README output for unchanged data matches the current README, apart from the copy fixes, so the migration diff is easy to review.
- The renderer stays all-or-nothing, and private repo values cannot reach the README.

**Non-Goals:**
- Generating the About or Connect sections. They are prose and badges with no second copy anywhere.
- Changing how featured cards look or rotate.
- Changing the stats and languages image alt text. It is generic and contains no data.
- Opening the All projects `<details>` by default when a private card is clicked.

## Decisions

### D1. One marker pair per region, one replace helper
Add `hero`, `projects` and `stack` regions using the existing marker style: `<!-- NAME:start (generated by scripts/render_profile.py; edit data/profile.yml) -->` … `<!-- NAME:end -->`. Generalise `update_readme(text, block)` into `replace_region(text, name, block)` and apply it once per region, featured included. A missing marker raises `RenderError("README is missing the NAME:start/NAME:end markers")`.

*Alternative:* one marker pair from hero to end of the stack section. Rejected: About would be swallowed and become generated, or need its own source in `profile.yml`.

### D2. `projects.private` is the single home for private projects
```yaml
projects:
  private:
    - title: SwingTrade AI
      version: v0.25
      summary: NSE swing-trade screener with 21 setup detectors, …   # All projects line
      stack: [Django, Celery, Redis, React, TypeScript]
      card:                                                          # present ⇒ featured candidate
        repo: ""
        summary: "NSE swing screener: 750+ stocks, …"
        tags: [Django, Celery, Redis, React, TypeScript]
    - title: NSE Signal Bot & Backtester
      with: Tilak004                                                 # renders (w/ [@Tilak004](…))
      summary: …
      stack: [Python, Pandas, Pine Script, Streamlit]
```
`gather()` builds the private card candidates from entries with `card`, in file order, by merging `title` and `version` into the card dict, so `render_card()` and `featured_block()` keep receiving the same shape. Rotation rules are unchanged: they apply to the candidates only.

*Alternative:* keep `featured.private` and point it at projects by title. Rejected: a renamed title would silently break the reference.

### D3. Public table: curated rows, then API fallback
```yaml
projects:
  public:
    hide: [ImageResize]          # optional
    repos:
      - repo: movie-app-v2
        label: CINE DB          # optional; shown in brackets after the repo link
        stack: [React, TypeScript, Django, PostgreSQL, Playwright]
        about: Movie & TV tracker on TMDB with ML recommendations and E2E tests
```
Rows are: every repo in `repos` that exists, is public and is not a fork, in file order; then every other public, non-fork repo that is not hidden and is not `{user}/{user}`, newest `pushed_at` first, with `stack` = `[language]` (or empty) and `about` = the API description cut at the first sentence or 100 characters. A `repos` entry that no longer exists is skipped. A rename or deletion must not fail the daily run.

The counts in `<summary>` are `len(private)` and `len(rows)`.

### D4. Alt text built from the same data as the image
- Hero: `"{name} — {roles}. " + ". ".join(tagline lines) + "."`, escaped like the featured alts. Tagline lines start with a capital, so they are joined as sentences.
- Stack: `"Tech stack. " + ". ".join(f"{label}: {', '.join(tools)}") + "."`, with group labels converted to title case ("DATA & ML" becomes "Data and ML"), as the README has them today.
The hero keeps its `<a href="https://github.com/{user}">` wrapper. Without it GitHub links the image to the raw SVG.

### D5. Leak check on the final README string
After all regions are replaced, check that no non-empty `card.repo` value (and no `name` part of it) occurs in the README text. On failure raise `RenderError("a private repo name would be written to README.md")`, without the value. The check runs on the final string, so it also covers future regions.

*Alternative:* trust the code path. Rejected: the cost is one loop, and the rule is a hard privacy line.

### D6. Markdown escaping in generated text
Table cells escape `|`. Alt attributes escape `&`, `<`, `>` and `"` (as `featured_block` does). Text in the list and table is written as is. The copy comes from the owner, and `*`/`_` formatting in it is allowed.

## Risks / Trade-offs

- [The API description for an uncurated repo is poor or empty] → The row still renders. The owner adds a `repos` entry or a `hide` item. The daily run never fails on it.
- [The `name` part of a private repo matches a common word in other copy, such as `blog`] → The leak check would fail a valid render. Mitigation: match only the `owner/name` value and the bare `name` when it is longer than a few characters and occurs as a whole word. Document this in the script.
- [Migration changes wording the owner liked] → Migrate the current README list text as is. The only exception is the Swing-Trade Research mismatch. The owner chose the title "Swing-Trade Research", and the card's "cost-aware" wording is kept.
- [The specs extend a change that is not archived yet] → Archive `glass-profile-readme` before this change, so the delta lands on existing main specs.

## Migration Plan

1. Move `featured.private` into `projects.private`, and copy the README's private list and public table into `profile.yml` as is.
2. Add the three marker pairs around the existing hero, All projects and stack blocks in `README.md`.
3. Render locally. The README diff must show only the copy fix, plus any alt or table text that comes out different from today's hand-written version. Review that diff.
4. Push on a branch and review the rendered profile in desktop light and dark and on mobile before merging, as CLAUDE.md requires.

Rollback: revert the commit. The old renderer ignores the new markers and the `projects` key. Restore `featured.private` from the revert.
