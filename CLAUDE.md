# CLAUDE.md

GitHub profile README repo for SanjayJoshi116. `README.md` renders on the profile page.

## Layout

- `README.md`: profile page. Images come only from `assets/…`.
- `assets/*.svg`: flat dark SVG cards (hero with contribution chart, featured cards, private pulse strip `pulse.svg`, system diagram `pipeline.svg`, stack, stats, langs, connect buttons). **Generated; don't hand-edit.**
- `data/profile.yml`: source of truth for intro, `site.url`, featured allowlist (optional `case` blocks), projects (private list, card copy and diagram stages, public table, `groups` and `hide`), stack, connect links, languages.
  - `projects.private[].diagram.stages`: at most one private project has one, with 3–6 stages, each with a `title` and a `detail`. Each stage title must fit on one line and its detail on two, or the render fails. It renders as `pipeline.svg` inside a collapsed "How <title> works" `<details>`.
  - Private card versions: with a token, read from the card repo's default branch (first of `VERSION`, `pyproject.toml`, `package.json`, or `card.version_from: <path>`; any `.toml`/`.json` is parsed, a leading `v` and UTF-8/UTF-16 BOMs are fine), shown as `v<major>.<minor>` in the cards, pulse, All projects and the site. `version` is the fallback without a token or with `version_from: manual` (any case); projects without a card always use it. The repo must be readable before its files are read. An unreadable or invalid version fails the render; a bad or misplaced `version_from` fails every run, token or not. Private project titles must be unique. Errors name cards and projects by number (`private card #N`) only.
  - `case` (on `featured.public` entries and private projects with a `card` only): `problem`, `approach` (list), `outcome`, optional `slug`. A private project with a diagram may leave out `approach` (its stages are used). Validated on every run; only the site uses it. Unknown or missing fields, a `case` anywhere else in the file (another project, or nested under `card`, `diagram`, a group…), a duplicate slug, or a project with a case sharing its title with another featured candidate fail the render.
  - `projects.public.groups`: rows of related repos (title, stack, about, repos; all required), shown after the plain `repos` rows. A repo listed twice across `repos` and groups fails the render. Missing or hidden members are skipped, and empty groups are omitted. The public count includes group members.
- `scripts/render_profile.py`: reads `profile.yml` + GitHub API, renders `assets/` and the `hero`, `featured`, `pulse`, `diagram`, `projects`, `stack`, `activity` and `connect` marker regions in `README.md`. Every marker pair must exist. Public repos come from `public_repos()`: with a token, GraphQL `repositories(privacy: PUBLIC)` so GitHub filters private repos out server side; without one or on HTTP 401, unauthenticated REST; all pages. Never list repos with the token through an endpoint that can return private ones. `pulse` (private card projects by last push) needs a token, so without one `pulse.svg` and the `pulse` region are left as they are (the kept `pulse.svg` is still leak-checked); with a token but no card repos, both are removed. Pulse ages count IST calendar days. The diagram uses no API data, so its output is the same with or without a token; with no diagram, `pipeline.svg` is deleted.
- `site/`: GitHub Pages landing page, built by `render_profile.py --site` from the same data in the same all-or-nothing pass. It is native HTML/CSS, not the README's SVGs (no `site/assets/`): home `index.html` (hero text + inline theme-coloured contribution chart, Now from pulse data (left out without a token), featured cards, stack, all projects, activity, connect) and one case-study page per `case` block at `projects/<slug>/`, built whether or not the README features that project and always linked from its All projects entry ("Case study →"). Featured cards and Now rows link to it too. Preview tags use the plain project title; only the tab `<title>` adds the profile name. Every page has its own `og.png` and preview tags, follows light/dark (`PAGE` tokens), and prints as a one-page CV (`@media print`): `.print-only` shows only on paper (contact addresses), `.screen-only` marks everything left off it (chart, Now, public table, activity, connect, footers, case links). Mark any new home-page section `.screen-only` unless it belongs on the CV, and re-check that the printout fits one page. Gitignored, never committed; holds exactly the last site run's files. `site.url` (https, trailing `/`) is used only for absolute preview-tag URLs; links inside the site are relative. Live at `sanjayjoshi116.github.io/SanjayJoshi116/` (Pages source: GitHub Actions).
- `.github/workflows/render-profile.yml`: renders daily (02:17 UTC, 07:47 IST), on push to `main` touching `data/profile.yml` or the script, and on `workflow_dispatch`. It also polls hourly from 06:17 to 23:17 IST (`47 0-17 * * *` UTC). GitHub schedules are best-effort: most polls are dropped and the rest start late (observed ~4 runs/day, forced render included, Oct 2026), so updates are a few times a day, not hourly. Each poll runs `render_profile.py --fingerprint` (a digest of push times for public repos, minus hidden ones and the profile repo itself, and private card repos, plus today's IST date; kept in `actions/cache`) and renders only if the digest changed, so the first poll of each day always renders. The poll logs only `changed`/`unchanged`, never names, times or the digest. Commits only when output differs. Renders always pass `--site`; after a render on `main` a `deploy` job publishes `site/` to Pages (`github-pages` environment, `main` only), skipped polls and failed renders deploy nothing. The render job only stages the new digest; a `remember` job saves it as the poll's digest after `deploy` succeeds (after the render on other branches), so a failed deploy is retried by the next poll. Other branches upload `site/` as the `site-preview` artifact instead.
- `openspec/specs/`: main specs. `openspec/changes/`: active changes; `archive/` holds finished ones (e.g. the glass-profile-readme redesign).

## Commands

```sh
# Python 3.12 in CI; 3.11+ locally to parse a card repo's .toml version file
pip install pyyaml==6.0.2
python scripts/render_profile.py                   # local; unauthenticated API, may hit rate limit
PROFILE_TOKEN=... python scripts/render_profile.py --require-token   # README + assets only
pip install pillow==13.0.0
PROFILE_TOKEN=... python scripts/render_profile.py --require-token --site   # as CI runs it; also builds site/
```

## Rules

- To change content, edit `data/profile.yml`, then re-render. Never edit `assets/*.svg` or any README region between `<!-- NAME:start` and `<!-- NAME:end -->` by hand (`hero`, `featured`, `pulse`, `diagram`, `projects`, `stack`, `activity`, `connect`). About is hand-written.
- Renderer is all-or-nothing: it renders in memory and writes nothing on any error. Keep it that way.
- Text never overflows silently. The render fails on a word wider than its text box (any wrapped copy), a stack row or connect label that doesn't fit, a diagram stage over its lines, or a pulse row whose title and version would reach the widest age label (`active 99mo ago`). On the site, each `og.png` title line (profile name or project title) must fit (measured with the real font) or the render fails. Too many lines in the hero intro, a card summary or an `og.png` body end with "…" instead.
- Private repos: never enumerate them, and never write a private repo name or the token to assets, the README, logs or commits. Only `projects.private[].card.repo` values in `profile.yml` are considered; the renderer fails if one would appear in the README, `pulse.svg`, `pipeline.svg`, any `site/**/index.html` (case-study slugs included) or the text drawn into any `og.png`. For pages only what they say is checked (text, link, label and preview-tag values), not markup or CSS. Errors never print a slug or page path (a slug may equal a private repo name): case pages are named "case-study page #N". API errors carry the request URL, so a failed call on a private repo is never printed as-is: catch it and raise a numbered message, branching on `RenderError.status` (never on the message text).
- Style is flat cards (`design.md` D1): always dark in the README SVGs, following the light or dark theme on the site; glassmorphism was tried and dropped.
- SVGs and the site load no external resources (system font stack, inline CSS, no scripts, remote fonts or images) and must keep text contrast ≥ 4.5:1 on GitHub light and dark; the site's light and dark text tokens (`PAGE_TEXT`) are checked against both the page and card backgrounds by `check_contrast()`.
- `PROFILE_TOKEN` repo secret: fine-grained, read-only, on the allowlisted card repos only: Metadata: read, plus Contents: read used solely to read each card repo's version file (never logged or written; only the validated `v<major>.<minor>` label leaves the reader).
- Review the rendered profile and the `site-preview` artifact on a branch (desktop light and dark, mobile, a case-study page, and print preview fitting one page) before merging to `main`.
